# Orbit Pad 0.5.0

下载见 [GitHub Release v0.5.0](https://github.com/OYLT/Orbit-Pad/releases/tag/v0.5.0)。Android 包名保持 `app.orbitpad.controller`，versionCode 6，使用原发布签名；需要直连功能时请同时更新 Windows 接收端至 0.5.0。

## 页面

底部悬浮 Dock 属于 App 自身，不需要系统悬浮窗权限。主页是模板工作台：三种基础预设，布局预览、拖动按键、单独调整控件大小和显隐，以及映射与手感设置；可保存最多 24 个命名模板，重新加载或删除。模板和当前工作配置保存在 Android 私有偏好文件中。

连接页默认选中扫码，支持相机扫码与图片导入，识别成功后自动配对；二维码沿用电脑端现有的 `http://IPv4:端口/controller#pair=六位码` 格式。Rust 校验二维码格式与局域网地址，扫描不会打开任意网页。

连接页同时提供 USB、蓝牙和手动配对。主题页保留空白，供后续构建。关于页显示版本、系统要求、连接与输入方式、包名、项目地址及二维码组件信息。

手柄使用横屏全屏界面。设置中的“返回主页”保留会话并释放全部触点；从主页“进入手柄”恢复控制。管理页面与布局编辑期间不会发送游戏输入。

## 直连实现与使用

USB 走真实数据线上的 ADB reverse 通道，手机控制协议连接本机 `127.0.0.1:3210`，电脑把该 USB 通道转发到当前接收端端口。第一次使用需开启 USB 调试并在手机确认电脑授权。电脑端自带 Google 官方 platform-tools，点击“USB 连接”后选择手机，手机端再点击“连接 USB 手柄”。程序使用 `--no-rebind`，不覆盖其他服务的端口映射；正常退出只移除本次创建且仍指向本接收端的映射。

蓝牙走双方已配对的经典蓝牙 RFCOMM，服务 UUID 为 `873d421b-2c01-4b50-9cde-0836ab901a51`。Windows 使用自身 Winsock Bluetooth API 注册 SDP 服务并要求认证、加密；手机使用 Android BluetoothSocket，并把字节流提供给 Rust 控制核心。需要用户在系统设置先完成配对，电脑点击“蓝牙连接”，手机授权“附近设备”后选择该电脑。此实现不依赖蓝牙 PAN 或网络共享，也不引入第三方蓝牙 DLL。

两条直连通道均终止于电脑的 loopback 接口。`/api/direct/bootstrap` 仅允许本地来源获取当前配对码，随后仍走正常 token / WebSocket 认证流程。每条控制会话保留心跳、断线释放与前台重连机制。接收端只允许一个活动手柄。

原局域网手动配对与二维码格式兼容旧版接收端；直连自动握手需要新版电脑端。只运行 `npm start` 可使用局域网方式；USB 和蓝牙入口在 Windows 原生接收端中。

## 构建与文件

```powershell
npm run build:android
npm run build:windows
npm run test:android
npm test
python scripts/verify-release.py
```

输出为 `releases/OrbitPad-Android-v0.5.0.apk` 和 `releases/OrbitPad-Receiver-Windows-x64-v0.5.0.zip`。

扫码使用 Maven Central 的固定版本 ZXing core 3.5.3，校验 SHA-256；完整许可证包含在 APK 的 `assets/ZXING-LICENSE.txt`。相机只在扫码 Activity 前台打开，离开即释放。Android 12+ 的蓝牙连接只请求 `BLUETOOTH_CONNECT`，列出系统已配对设备，不在 App 中执行蓝牙扫描。

## 验证范围

本次使用 Redmi K40 Pro+（Android 16）和预览接收端验证。各套件的原始数据按版本保存在 `artifacts/redmi-v0.5.0-*/report.json`，Rust 协议检查位于 `artifacts/android-rust-v0.5.0/protocol-report.json`。Windows 便携包自检记录为 `releases/windows-self-test.json`。

最终 APK 共通过 97 项真机步骤：基础输入 45、设置 17、Dock / 模板 / 二维码图片 15、USB 9、相机 2、蓝牙 9。蓝牙检查在 Redmi 与本机完成系统配对后，实际通过加密 RFCOMM 输入、释放、后台断开和前台重连。Rust 单元测试 8 项、协议检查 76 项、Node / Windows 测试 10 项通过。详情见 [真机报告](REDMI-V0.5.0-TEST-REPORT.md)。

扫码图片测试使用实际接收端生成的 PNG，再经手机中的 ZXing 解码与 Rust 配对；该检查不等同于将实体手机相机对准实体显示器。USB 检查使用实际 USB 数据线通道。未针对具体游戏、反作弊、长时间温升或续航作兼容性结论。
